# Upgrade Notes — 0.8.0 Architecture Expansion

The 0.8.0 line introduced additive foundations after the earlier registry-focused architecture, including master data/history, durable jobs, documents, workflow, API/integrations, portals, enterprise identity, read models and operational tooling.

## Database

Apply migrations through the project pipeline only:

```bash
pnpm db:migrate
pnpm db:setup
```

Do not substitute `drizzle-kit push` for the production migration sequence. Manual SQL under `db/sql` is part of the security/integrity contract.

The migrations are additive by design; legacy snapshot text remains where historical truth requires it.

## Better Auth

Passkey/SSO/SCIM integrations use official Better Auth plugins. Reconcile the generated plugin schema with application migrations during release preparation rather than maintaining an unreviewed local fork of security-sensitive third-party schema.

## Workers and storage

Deploy the job worker separately from the Web process. Configure object storage before enabling document workflows or large imports. Privileged Platform operations retain a distinct execution environment.
